# 商单界面（真实 API）

项目列表、项目详情、流程图和集成页的默认流程都读取 `/api/v1/commercial`。刷新页面看到的是数据库里的状态。

节点操作把最近一次流程读取返回的 `updatedAt` 原样作为 `expectedUpdatedAt`。服务器以 `stale_write` 拒绝时，页面重新加载该项目，并说明数据已在别处变更；不会用新令牌自动再提交。

可选节点的「不适用」来自**同一模板版本**的已发布默认流程：实例读取不带 `isOptional`，页面只在默认模板的 `id` 与项目的 `templateVersionId` 一致、且节点名称唯一时，按名称使用模板上的 `isOptional`。对不上时不提供这个操作。

开放事项的编号和更新时间不在项目读取结果里。页面展示读取到的阻塞原因标题；关闭和取消只针对刚才写入接口返回的事项。刷新后不能再对已有事项提交关闭或取消。

发布节点完成后，当次响应里的发布记录和两条监控任务会显示出来。刷新后项目详情只保留 BV 号、发布时间和来源。

默认流程页只读。编辑草稿和发布新版本还没有接到后端。

测试环境灌入已有夹具（不会在应用启动时运行）：

```bash
bun run seed:commercial
```

该命令会先执行迁移，再调用 `seedCommercialFixtures`。重复执行不会覆盖已有主键。
